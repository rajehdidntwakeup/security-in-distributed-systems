The CIA Triad: Three Goals of IT Security

Confidentiality, Integrity, Availability: what they mean, how cryptography helps reach each one, and where you see it in practice every day.

Definition

Three goals, one security picture

ConfidentialityOnly authorized people can read data. Encryption keeps the content secret.
IntegrityNobody can change data without being detected. Hashes and signatures prove data is untouched.
AvailabilityData and systems are usable when needed. A dead server is useless, even if it is encrypted.

Every security measure protects at least one of the three. Lose any one of them and you have a security incident.

When a goal fails

Pick a goal and see what breaks

Lost when data leaks.

Goal 1 · Confidentiality

Cryptography: encryption keeps secrets

HTTPS / TLSBrowser ↔ server traffic is encrypted. Public Wi-Fi attacker sees sizes and IPs, not your password or cookies.
Full-disk encryptionBitLocker, FileVault, LUKS. Stolen laptop = unreadable ciphertext without the key.
E2E messengersSignal, WhatsApp. Only sender and receiver hold the keys; even the provider cannot read messages.

One line: encrypt data at rest and in transit, keep the keys with the people who need to read.

Goal 2 · Integrity

Cryptography: hashes and signatures prove "untouched"

Digital signaturesCode signing: Windows verifies an .exe really comes from the vendor and was not modified on the way.
SHA-256 checksumsLinux ISO downloads publish a checksum. Different hash = corrupted or tampered file.
Hash chainsBlockchain and tamper-evident logs: each block contains the previous block's hash. Changing old data breaks the chain.

One line: hash to detect change, sign to prove who approved the data.

Goal 3 · Availability

Cryptography's role: keep systems usable

Crypto cannot stop a DDoS flood itself, but it protects availability in three ways:

Encrypted backupsRansomware encrypts live data. An offline backup (or cloud-held key) restores the system.
Key managementLosing the only key = losing the data forever. Key escrow and backups keep encrypted systems accessible.
Authenticated protocolsTLS + certificates stop fake servers from impersonating the real service, so traffic keeps going to the genuine one.

Summary

Map: goal → tool → real-world example

GoalMain crypto toolExample
ConfidentialityEncryption (AES, TLS, PGP)Stolen laptop unreadable; Wi-Fi eavesdropper sees nothing
IntegrityHashes + digital signaturesSigned software update verified before install
AvailabilityKey management + encrypted backupsOffline backup survives ransomware attack

One goal is never enough: an encrypted but down server is useless, and an online but readable database is a breach.

Conclusion

Three goals, one habit

Encrypt for secrecy, hash and sign for trust, manage keys and backups so data stays usable. Security is not one castle wall; it is holding all three goals at once.

CIA = Confidentiality + Integrity + Availability
