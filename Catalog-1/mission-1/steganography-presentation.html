Fundamentals · How it works

Hide the existence: in the last bit

Steganography vs. encryptionEncryption scrambles content but reveals that a secret exists. Steganography covers it inside an ordinary file: the observer sees only the image.
LSB steganographyEach pixel has R,G,B values, 8 bits each. The message becomes a bitstream that overwrites the lowest bit of each channel; value shifts ≤ 1 of 255, invisible.

Runs fully client-side via JavaScript + HTML canvas: nothing is uploaded, output downloads as lossless PNG. Can you spot the difference between the two swatches? Nobody can. That is the point.

In the tool

Encode, decode: no key involved

EncodeLoad carrier image → type message → tool walks pixel channels, writes message bits into the LSBs → download stego PNG.
DecodeUpload the stego PNG → tool reads the LSBs back out → reassembles the message. No key needed: anyone can decode.
CapacityOne hidden bit per channel per pixel. A 1000×1000 image holds ≈ 375 KB of payload, and no more.
FragileAny lossy step (JPEG conversion, resizing, cropping, screenshots, social-media recompression) destroys the payload. Only PNG-to-PNG survives bit-exact.
stego.png → post to social media → JPEG recompression wipes every LSB stego.png → screenshot → message is gone

Conclusion

Good teaching tool, not a security tool

ClaimVerdict
Free, no install, client-side, no uploadTrue: data stays on-device
Invisible to the eye; lossless PNG outputTrue: payload survives
Message stays secretNo: no encryption, no password; anyone can decode
Hidden data undetectableNo: plain sequential LSB, zsteg & statistics catch it fast
Survives JPEG / screenshots / social mediaNo: any lossy step destroys the payload
No encryption inside: encrypt first

It demonstrates the idea perfectly: instant, invisible, fully client-side. But plain LSB hiding against anyone with zsteg is concealment, not security. Fine for learning, CTFs, watermarks, but not for real adversaries.
