Mission-5 · Asymmetric Encryption

RSA: One Lock, Two Keys

How a key pair distributes trust openly, what the factoring problem protects, and which attacks padding exists to stop. Runs alongside AES (Mission-4) in every real system.

Principle

Encrypt with one, decrypt with the other

Public key (n, e)Freely shareable. Anyone can encrypt a message to the owner, or verify their signature.
Private key (n, d)The only thing that can decrypt or sign. No secure channel is needed to distribute the public part: the key distribution problem is solved.

Security rests on the factoring problem: computing n = p·q from two large primes is instant, recovering p and q from n is practically impossible. RSA = Rivest, Shamir, Adleman, 1977.

The algorithm

Exponentiation mod n

p · q→n = p·q,φ(n) = (p−1)(q−1)→e = 65537→d = e⁻¹ mod φ(n)

c = me mod n   m = cd mod n

Because e·d ≡ 1 (mod φ(n)), decryption undoes encryption: m^(ed) ≡ m (mod n). Without d, reversing means factoring n. Keys: RSA-2048 minimum, 3072+ for long-term secrets.

Padding

Never raw RSA, always OAEP

Textbook RSA failsDeterministic (same message, same ciphertext) and malleable: c'=c·r² mod n decrypts to m·r². An attacker can multiply messages without knowing them.
OAEP fixes itInjects randomness (every encryption differs) and resists chosen-ciphertext attacks. Standard: RFC 8017. For signing, the same pair runs in reverse with PSS: sign with d, verify with e.

Raw RSA survives only inside textbooks and exam questions. Real code: padding.OAEP(...) or nothing.

Attacks

What actually breaks RSA

FactoringRecover p, q from n. RSA-768 fell in 2009 after months of computing. Defense: ≥ 2048 bit, fresh primes from a secure RNG (shared p = instant GCD break).
Padding oraclesBleichenbacher/ROBOT: a server that reports padding errors leaks enough to decrypt adaptive-ciphertext style. Defense: OAEP + constant error handling.
Textbook misuseSmall messages, no padding: m³ < n → just take the cube root. One message to many recipients → Håstad broadcast attack. Tiny d → Wiener recovers it.
MITM and quantumRSA does not authenticate by itself: swap the public key in transit, decrypt everything (fix: certificates). A working quantum computer runs Shor's algorithm → factor n fast. Migration: PQC (ML-KEM).

Brute force is not how RSA falls; implementation and usage mistakes are.

Asymmetric vs. symmetric

Different tools, one pipeline

Asymmetric (RSA-OAEP)Symmetric (AES-256-GCM)
KeysKey pair (public + private)One shared secret
Key distributionEasy: done in the openHard: needs secret channel
Speed1000–10000× slowerGB/s, hardware-accelerated
Bulk dataNo: 214 bytes per blockYes: arbitrary length
IntegrityTag via PSS signatureBuilt-in 128-bit GCM tag

Real systems are hybrid (TLS, PGP, Signal): RSA encrypts a fresh AES session key, AES-GCM (Mission-4) encrypts the data. RSA says who and carries the key, AES moves the data.

Never raw RSA, never textbook padding RSA-2048 + OAEP: keys in the open, trust from factoring
