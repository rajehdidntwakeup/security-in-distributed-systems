PGP: Encrypt for Anyone

One hybrid scheme for confidentiality and authenticity without infrastructure: what PGP is, how it combines both cipher worlds, and where it is used every day.

What is it?

Not a cipher: a packaging of ciphers

1991 · Phil ZimmermannE-mail encryption should be possible for everyone, not just companies. PGP is a program and a format.
OpenPGP · RFC 4880The format lives on as an open standard: keys, signatures and ciphertext have a defined wire format.
GNU Privacy GuardGnuPG (GPG) is the widely used open-source implementation: in practice "PGP" and "GPG" mean the same thing.

PGP answers symmetric or asymmetric? with: both, combined deliberately: a hybrid scheme. Each cipher does the job it is fastest at.

How it works

Hybrid encryption: fast cipher, small RSA

message→AES session key (random)→ciphertext +session key → RSA with public key→encrypted key

1. The (large) message is encrypted with a fresh random session key using fast symmetric AES.
2. Only that small key is encrypted with the recipient's public key.
3. Decryption: the private key unlocks the session key, the session key unlocks the message.

Why this is the sweet spotRSA alone can't bulk-encrypt and is slow; AES alone can't be sent to a stranger. One small RSA operation per message plus AES for all the data: fast and keyless to distribute.

Authenticity

Signatures and the web of trust

hash (SHA-256)→sign: private key→signature→verify: public key→valid?

A signature binds the message to the private key holder: anyone can verify integrity and authorship, nobody can forge it without d. Encrypt and sign combine freely.

Web of trustNo certificate authority: users sign each other's public keys. Trust in the friend who verified Alice extends partially to Alice's key.
Today's practiceMost people verify a key fingerprint once, directly (in person, video call) instead of building trust chains.

Comparison

Symmetric vs. PGP

Symmetric (AES)PGP / hybrid
KeysOne shared secretKey pair: public + private per person
Key exchangeHard: confidential channel needed firstEasy: public key shared openly
SpeedVery fast, any sizeSlower per op, but only the session key is RSA
Scalabilityn people → n·(n−1)/2 pair keysn people → n key pairs
Applied toChannels: disk, VPN, TLS bulk, Wi-FiObjects between identified persons: mail, files
Identity / integrityNone by itselfBuilt in: every message can be signed
Trust modelPre-shared secret or PKI/CAWeb of trust, fingerprint check, no CA

Pattern: symmetric = both sides already share a secret context. PGP = strangers who have never arranged anything can still communicate securely.

Typical use

Where PGP runs today

E-mail encryptionEnd-to-end encrypted e-mail (Thunderbird): even the provider cannot read it.
Signed e-mailProves a message really comes from the sender: defense against phishing.
File exchangeEncrypt archives sent to partners, lawyers, journalists.
Software signingReleases, installers, git commits: users verify authenticity.
Secrets & backupsPassword managers, LUKS recovery data, encrypted backups.
WhistleblowingSecureDrop: journalists publish keys so sources can encrypt to them anonymously.

Wins in practice  solves key distribution, works end-to-end with no infrastructure, confidentiality + authenticity + integrity in one scheme, one key pair per person, open standard.
