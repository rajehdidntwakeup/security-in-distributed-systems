Mission-4 · Symmetric Encryption

AES-256-GCM: One Key, Both Directions

How the standard cipher keeps data confidential and untampered, and what breaks it in practice.

Principle

One shared secret key

Ek(P) = C   Dk(C) = P  (same k on both sides)

Same key encrypts and decrypts. Both parties must share it over a confidential channel in advance: the key distribution problem. Used everywhere bulk data moves fast: TLS, disk encryption, VPNs, Wi-Fi.

The algorithm

AES, 14 rounds of scramble

state→SubBytes→ShiftRows→MixColumns→AddRoundKey→×14

Each round substitutes (S-box), shifts and mixes the 4×4 state bytes, then XORs a round key from the 256-bit master key. Result: avalanche, one flipped plaintext bit changes about half the ciphertext bits. No practical break exists; brute force over 2256 keys is hopeless.

Mode of operation

GCM: secrecy plus a tag

P⊕keystream→C→GHASH→tag
Nonce (96 bit)Seeds the keystream. Must be fresh per message under the same key.
Tag (128 bit)GHASH over the ciphertext: detects any modification. Decryption verifies first, releases plaintext only on match.

Code · Python

Four lines, done right

key = AESGCM.generate_key(bit_length=256) nonce = os.urandom(12) # fresh per message ct = AESGCM(key).encrypt(nonce, message, None) pt = AESGCM(key).decrypt(nonce, ct, None) # tag verified first

Keys from a password? Stretch it with a salted KDF (scrypt) first. Full runnable demo: aes_demo.py.

Attacks

What actually breaks AES

Nonce reuseSame key + same nonce = same keystream, a two-time pad: C₁⊕C₂ = P₁⊕P₂, the keystream cancels and one known message leaks the other. No AES broken.
Key managementKeys in source code, passwords instead of random keys, keys left in memory. The usual real-world cause of "broken AES".
Missing authenticationWithout a tag, ciphertexts are malleable, and CBC error messages leak plaintexts (padding oracles).
Side channelsTiming and power attacks on implementations. Defense: constant-time, vetted libraries. Never roll your own AES.

Brute force was never the threat; 2256 keys end that discussion.

Symmetric vs. asymmetric

Different tools, one pipeline

Symmetric (AES-GCM)Asymmetric (RSA / ECC)
KeysOne shared secretKey pair (public + private)
Key distributionHard: needs secret channelEasy: public key is public
SpeedGB/s100–1000× slower
Bulk dataYes: arbitrary lengthBounded by key size
QuantumAES-256 stays safe (Grover)Broken (Shor)

Real systems are hybrid (TLS 1.3): asymmetric crypto authenticates the peers and derives the session key, AES-GCM then encrypts the whole session. Asymmetric says who, symmetric moves the data.

Never reuse nonces, never hand-roll AES AES-256-GCM: key ‖ fresh nonce ‖ tag
