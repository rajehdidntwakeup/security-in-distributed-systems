cryptographic hash functions

A fingerprint for data

How SHA-256 turns any input into a fixed-size digest and how comparing digests proves data hasn't changed.

What a hash function does

input: any size
2 bytes … 2 GB → SHA-256
one-way function → digest:
256 bits, always

Same input → same digest, every time. You can hash a password or a movie and get exactly 64 hex characters back. Going from digest back to input is practically impossible.

Four properties that make it useful

Deterministicthe same input always produces the same hash
One-waypractically impossible to reverse the digest
Collision-resistantno two different inputs known to share a digest
Avalanche effectone changed bit → the whole digest changes

Where hashes guard data

Software downloadspublishers post digests; package managers recompute to catch modified files
Password storagestore the hash, never the password
Digital signaturessign the digest, not the document
Blockchains & tableseach block links to the previous block's digest; fixed-length digests make comparisons cheap
summary

Detect corruption, prove untampered, store safely, sign

A hash is a fingerprint: cheap to compute, honest by nature. If the fingerprint you check doesn't match the one you were given, the data changed -> don't trust it.
